# Tikabhairab Rajkulo — Living Heritage Map

Interactive web platform for the **13 km Tikabhairab Rajkulo** — a Licchavi-era hill-fed canal in Lalitpur, Nepal. Built from field GPS survey (May 2022) + AutoCAD alignment drawings. Available in **English and Nepali (नेपाली)**, with the survey data free to download under **CC BY 4.0**.

Live site: <https://lonerdonor.github.io/Tikabhairav-Rajkulo-Story-Map/> · in Nepali: add `?lang=ne`

The site is a single, static, dependency-free page that runs from any web server (including GitHub Pages) or directly from `file://`.

---

## What the survey data show

All of these are computed live from `site/data.js` in the site's **Analysis** tab, so they always match the data:

- **Year-round water only in the first 3,124 m.** Every perennial section lies between the intake and station 3+124 m (sections 1–51); from 3+441 m on, every section with a flow record is seasonal.
- **Contamination starts near the intake.** The first contamination point (POI 1, an outflow) is at about 0+344 m; sewage was first recorded in the water at section 14 (0+509–0+531 m).
- **Sewage or waste in 30 sections (3.55 km)** — 2 of 48 sections with a water-quality record upstream of 3+124 m, but 28 of 34 downstream of 3+441 m.
- **Silt almost everywhere:** recorded in 67 of 76 sections with a silting record (88 %).
- **Still a built canal:** 81 of 83 sections with a lining record are lined; a typical open section is 60 cm × 35 cm.
- **Lost from view for 1.73 km:** the canal could not be seen in 9 sections, 8 of them between 3.6 and 8.4 km; 7 sections run through hume pipes.

The scripts resolve all project paths relative to their own location (`scripts/`), so run them from anywhere — e.g. `python scripts/build_thumbnails.py`. Scripts that read the survey sources take the **Rajkulo All Documents** folder with `--src`, or from the `RAJKULO_SRC` environment variable (they also look in `D:\Rajkulo All Documents` and `~/Downloads/Rajkulo All Documents`).

## Regenerating data

After editing the source Excel (`CANAL_Survey.xlsx`) or the source gpkg:

```bash
python scripts/build_platform_data.py --src "D:\Rajkulo All Documents"
```

This replaces the `CANAL_SECTIONS` block in `site/data.js` in place (`CANAL_POIS` and `CANAL_HISTORIC` are left untouched), refreshes `site/downloads/`, and writes into `data/`:
- `canal_sections.json` (inspection format)
- `canal_sections.js` (the `CANAL_SECTIONS` block)
- `canal_base_alignment.json` (the `टि-१` main alignment as MultiLineString; skip with `--skip-base`)

Add `--copy-photos` to also copy newly referenced original photos into `site/photos/`.

### How the section fields are derived

| Field | Source | Notes |
|-------|--------|-------|
| `chainage` | Excel col AD (formula) | Running distance at the **end** of the section (previous chainage + section length). Parallel branches (e.g. PDF# 91–93, 99–102) restart from their upstream section, so chainage is a main-line distance. The script evaluates the formulas itself, because a workbook last saved by openpyxl has no cached formula values. |
| `zcoord` | Excel col AE (formula) | **Interpolated**, not measured: a straight line from 1,477.16 m at the intake to 1,314.02 m at chainage 11,773.3 m. |
| `wq_list` / `wq` | Mergin multi-select | Every recorded value is kept in `wq_list`; `wq` is the worst of them (Sewage > Waste Dumping > Storm Water > River Quality). |
| `condition` | derived | Lost if the canal was not seen; Critical = sewage/waste + silting; Poor = sewage/waste; Fair = silting; Good otherwise; **No data** when nothing was recorded (including the 12 CAD-only sections). |
| `coords` | gpkg `Survey_new` by Mergin fid | The 12 sections without a Mergin fid keep the approximate geometry already in `site/data.js` and are drawn dashed. |

### Photos

The original photos (~1.5 GB) are not in git. After adding or replacing photos:

```bash
python scripts/build_thumbnails.py --src "D:\Rajkulo All Documents"
```

It writes the two web sizes, applies EXIF rotation and strips all metadata. It is re-runnable; only missing or outdated files are rebuilt (`--force` rebuilds all).

### Report

```bash
python scripts/build_figures.py
python scripts/build_docx.py
python scripts/publish_report.py   # report PDF + Study-tab diagrams for the site
```

## Languages

The whole interface — menus, legend, section panels, findings, tour and downloads — switches between **English** and **Nepali** with the button in the top corner. The choice is remembered on that device, and `?lang=ne` / `?lang=en` in the URL sets it directly (useful for sharing with ward offices). Nepali uses Devanagari digits (३,१२४ मि.).

All text lives in `site/i18n.js`; numbers in the findings and tour are `{placeholders}` filled from the data, so both languages always agree. Field notes, place labels and POI comments stay in English as the surveyors recorded them.

> The Nepali text was drafted for this project and should be checked by a native speaker before official use.

## Tour mode

Click **Take the tour →** on the splash screen, or visit any URL with `#tour=1`. The tour is a 10-stop sequence: the intake, the year-round upper reach, where contamination starts, where the canal turns seasonal, the reach lost from view, piped and buried sections, settlements crossed, the historic network, the end at Lagankhel, and how to explore further. Stops are listed in `TOUR_STOPS` in `site/app.js`; their text is in `site/i18n.js` (`tour.N.t` / `tour.N.b`).

- Keyboard-navigable filters, tabs, legend chips and search results
- ARIA roles on tablist, dialogs, listboxes, toolbar; labels translated with the interface

- High-contrast text alternatives next to colour-coded chips

## Known limitations

- **12 sections** (PDF# 52, 96–99, 101–107) are defined in the CAD drawings but were not GPS-walked in May 2022. They have approximate placeholder geometry (drawn dashed), no field attributes, and show as **No data**.
- **Elevations are interpolated** linearly along the chainage. No bed levels were measured, so the site and report draw no hydraulic conclusions; a level / total-station survey is needed for that.
- The photo viewer shows 800 px images; full-resolution originals are not published.
- **1 photo** referenced by the data (`IMG_20220508_150014.jpg`) was not found in any source folder.
